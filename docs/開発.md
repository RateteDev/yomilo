# 開発

## 構成

処理の基本経路は、**厳格Markdownソース → 構造化 → 構造化文書 → 描画準備 → 描画用文書 → 描画 → 描画結果**である。
語彙は[用語集](用語集.md)、判断の経緯は[ADR](adr/)を参照する。

- `crates/yomilo-core/` — 構造化、入力診断、正規化、描画準備と公開文書モデル
- `crates/yomilo-wasm/` — `@yomilo/wasm`。
  Rustからの型とWASM、Node向けとWorkers向けの入口、`createYomilo`を供給
- `packages/yomilo-html/` — `@yomilo/html`。
  本文のHTMLとフック、frontmatterと入力の検査、カードの取得
- `packages/yomilo-theme/` — `@yomilo/theme`。
  本文HTMLへそのまま当てる最小テーマのCSS`minimal.css`
- `experiments/phase0-rust/` — 成立性検証のソース。
  **製品コードではない**

## 検査

Rust workspaceとBun workspaceは同居し、lockfileはそれぞれ持つ。
ツール版は`mise.toml`を正とし、WASMと型の準備は明示的に行う。

```sh
just setup
just wasm-build   # 初回、またはRustの契約・実装を変更したとき
just core-ci      # Rustだけ。Bunは不要
just html-ci      # 準備済みWASMを使い、内部でRustを起動しない
just ci-local
```

HTMLパッケージのexportsはTSソースで、素のNodeからの直接実行は対象外とする。
本文のHTMLはアイコンへ表示寸法を指定せず、メディアの比率は`data-ratio-width`と`data-ratio-height`、素材の寸法は`data-intrinsic-width`と`data-intrinsic-height`、表の列揃えは`data-align`へ保持する。
`/engine`の`renderArticleBody`は本文のHTMLとフックだけを返し、開閉の初期状態は`data-fold`、図の拡大の指定は`data-zoom`、カードの取得状態は`data-icon-state`へ残す。

## リリース

版はルートの`package.json`の`version`だけが持ち、各パッケージへは詰めるときに書き込む。

1. ルートの`package.json`の`version`を上げてコミットする。
2. `v{version}`の注釈付きタグを、リリースノートを本文にして打ち、pushする。
3. Release のワークフローが`just pack`で3つのtarballを作り、タグの本文をノートにしてGitHub Releaseへ添付する。

手元で配布物を確かめるときは`just pack`を実行し、`dist/`のtarballを利用側から`file:`で指定する。
