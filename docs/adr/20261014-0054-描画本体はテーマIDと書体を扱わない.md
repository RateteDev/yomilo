# 描画本体はテーマIDと書体を扱わない

## 背景

移設では出力の一致を優先したため、`obsidian` と `snow` の識別子がスクリプトとCSSに固定され、書体（Moralerspace）とその原本が描画本体へ入った。
結果として描画本体が特定サイトの選択を前提にし、別の見た目を選ぶ利用先は本体のソースを書き換える必要があった。

## 判断

### テーマの識別子と切り替えは利用側の表示層が持つ

テーマの一覧、初期の識別子、切り替えの操作は利用側の表示層が持つ。
描画本体の出力とソースには、テーマの識別子が現れない。

**根拠**

- どのテーマを使うかは利用先の都合であり、本体が決められない。
- 切り替えは操作スクリプトの仕事であり、本文のHTMLを出す本体の仕事ではない。

### 書体はテーマの資産とする

書体の原本と、そこから作る埋め込み用の字形は利用側のテーマが持つ。
描画本体は書体名も原本の場所も持たない。

**根拠**

- 書体は意匠の値であり、テーマによって変わる。
- 本体が原本を持つと、第三者資産と容量が配布物へ入る。
